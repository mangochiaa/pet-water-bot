# Pet Water Tracker

Telegram-бот на Python, который помогает владельцам питомцев следить за тем, как часто и сколько пьют их питомцы, и подсказывает дневную норму воды.

Данные хранятся в SQLite: по умолчанию в файле `bot.db` рядом с `bot.py`, путь можно поменять переменной `DB_PATH`. Если рядом лежат старые `pets.json` и `water_log.json`, при первом запуске они автоматически переносятся в базу и удаляются.

## Возможности

- `/start` — приветствие и меню с кнопками
- `/add_pet` — пошаговое добавление питомца: имя → вид кнопкой → вес в кг → возраст в годах
- `/pets` — список всех питомцев (вид, вес, возраст)
- `/water` — отметить, что питомец попил воды: выбор питомца, затем «💧 Просто отметка» или «📏 Указать мл»
- `/stats` — сколько раз и сколько мл выпито сегодня
- `/stats_week` — то же за последние 7 дней
- `/top` — топ питомцев по числу отметок за неделю
- `/norm` (кнопка «📊 Норма воды») — рекомендуемая дневная норма воды и прогресс за сегодня
- `/delete_pet` (кнопка «🗑 Удалить питомца») — удалить питомца вместе со всеми его отметками
- `/help` — справка
- `/cancel` — отменить добавление питомца или ввод объёма

### Добавление питомца

1. Имя (до 50 символов).
2. Вид — кнопками: 🐶 Собака, 🐱 Кот, 🐹 Грызун, 🐦 Птица, ❓ Другое. Для «Другое» бот попросит написать название (например, «кролик»).
3. Вес в кг — больше 0 и до 500, можно дробный (`4.2` или `4,2`).
4. Возраст в годах — больше 0 и меньше 50, можно дробный (`0.5` — полгода).

### Отметка воды

После выбора питомца в `/water`:

- **💧 Просто отметка** — запись без объёма (в базе `amount_ml = NULL`);
- **📏 Указать мл** — бот попросит число: больше 0 и не больше 2000 мл.

В `/stats` и `/stats_week` объём суммируется; отметки без объёма считаются как 0 мл, но учитываются в количестве отметок.

### Удаление питомца (`/delete_pet`)

1. Бот показывает список ваших питомцев кнопками (если питомцев нет — «У вас пока нет питомцев.»).
2. После выбора просит подтвердить: «Удалить {имя}? Все отметки о питье тоже будут удалены.» — кнопки **✅ Да, удалить** и **❌ Отмена**.
3. При подтверждении питомец удаляется из `pets`, а все его записи — из `water_log`, в одной транзакции. Ответ: «Питомец {имя} удалён.»
4. При отмене ничего не удаляется, бот возвращает главное меню.

Удалить можно только своих питомцев: каждый запрос к базе фильтруется по `user_id`. Удаление необратимо.

### Норма воды (`/norm`)

```
норма_мл = вес_кг × базовый_коэффициент × возрастной_множитель
```

| Вид | Базовый коэффициент, мл/кг |
|---|---|
| Собака, Кот | 50 |
| Грызун, Птица | 100 |
| Другое | расчёт недоступен |

| Возраст | Множитель |
|---|---|
| меньше 1 года | 1.3 |
| от 1 до 7 лет | 1.0 |
| старше 7 лет | 1.2 |

Пример вывода:

```
🐶 Тайсон (Собака, 13 кг, 5 лет): 650 мл/день
Сегодня выпил: 400 мл (62% от нормы)
```

Строка «Сегодня выпил» появляется, если за сегодня есть отметки с указанным объёмом. У питомцев, добавленных до появления возраста, норма считается как для взрослых (множитель 1.0) — бот пишет об этом под списком. Норма ориентировочная и не заменяет консультацию ветеринара.

## База данных

Файл базы создаётся автоматически: по умолчанию `bot.db` рядом с `bot.py`, либо по пути из переменной окружения `DB_PATH` (папка создаётся, если её нет). Таблицы:

**pets** — `id`, `user_id`, `name`, `species`, `weight`, `created_at`, `species_code`, `custom_species`, `age_years`

- `species_code` — `dog` / `cat` / `rodent` / `bird` / `other`
- `custom_species` — своё название вида для `other`
- `species` — человекочитаемое название (оставлено для совместимости)
- `age_years` — возраст в годах (`NULL` у питомцев, добавленных до этой версии)

**water_log** — `id`, `pet_id`, `user_id`, `timestamp`, `amount_ml`

- `amount_ml` — объём в мл или `NULL` для «просто отметки»

### Миграции

При каждом старте бот проверяет схему и при необходимости обновляет её, данные не теряются:

- недостающие колонки `pets` добавляются через `ALTER TABLE`;
- у старых питомцев заполняется `species_code` по тексту в `species` («Собака» → `dog`, «Кот»/«Кошка» → `cat` и т.д.); неизвестный текст → `other`, а сам текст переносится в `custom_species`;
- если в `water_log.amount_ml` стоит `NOT NULL` (прошлая версия бота), таблица пересобирается в одной транзакции, чтобы разрешить `NULL`; старые нулевые значения становятся `NULL` — объём для них не вводился.

Если рядом лежат старые `pets.json` и `water_log.json`, они тоже переносятся в базу, после чего удаляются.

## Требования

- Python 3.9 или новее
- Токен бота от [@BotFather](https://t.me/BotFather)
- Модуль `sqlite3` уже есть в стандартной библиотеке Python

## Установка и запуск

1. Клонируйте репозиторий или скопируйте файлы проекта.

2. Создайте виртуальное окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

На Windows вместо `source .venv/bin/activate` используйте `.venv\Scripts\activate`.

3. Создайте файл `.env` по образцу:

```bash
cp .env.example .env
```

4. Откройте `.env` и вставьте токен:

```
BOT_TOKEN=123456:ABC-ваш-токен-от-BotFather
```

5. Запустите бота:

```bash
python bot.py
```

6. В Telegram найдите своего бота и отправьте `/start`.

При первом запуске со старыми JSON в логе будет строка вроде «Миграция JSON → SQLite завершена», после чего появятся только `bot.db`.

## Деплой на Railway

Бот работает через long polling, HTTP-порт ему не нужен. В корне лежит `Procfile`:

```
worker: python bot.py
```

### Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от [@BotFather](https://t.me/BotFather) |
| `DB_PATH` | на Railway — да | Путь к файлу базы. Для Railway Volume: `/data/bot.db`. Если не задан — `bot.db` рядом с `bot.py` |

Файл `.env` в репозиторий не попадает, поэтому на Railway переменные задаются в панели.

### 1. Подключить репозиторий

1. В [Railway](https://railway.com) создайте проект: **New Project → Deploy from GitHub repo** и выберите этот репозиторий.
2. Railway сам соберёт Python-проект по `requirements.txt` и будет автоматически деплоить каждый push в `main`.
3. Проверьте **Settings → Deploy → Start Command**: там должно быть `python bot.py` (берётся из `Procfile`; если поле пустое или другое — впишите вручную).

### 2. Создать Volume для базы

Без Volume файловая система контейнера временная: при каждом деплое или перезапуске `bot.db` удаляется вместе со всеми питомцами и отметками.

1. В проекте нажмите **Create → Volume** (или кликните правой кнопкой по холсту проекта → **Volume**).
2. Выберите сервис бота и укажите **Mount Path**: `/data`.
3. Сохраните — Railway перезапустит сервис с примонтированным диском.

### 3. Задать переменные

1. Откройте сервис бота → вкладка **Variables**.
2. Нажмите **New Variable** и добавьте:
   - `BOT_TOKEN` = ваш токен;
   - `DB_PATH` = `/data/bot.db`.
3. Railway применит переменные и передеплоит сервис.

В логах деплоя (**Deployments → View Logs**) должна появиться строка `База данных готова: /data/bot.db`.

Чтобы перенести существующую локальную базу, её нужно один раз загрузить в Volume; иначе на Railway бот начнёт с пустой базы.

### ⚠️ Только один экземпляр бота

Нельзя запускать бота одновременно локально (`python bot.py`) и на Railway с одним и тем же токеном: Telegram отдаёт обновления только одному получателю и вернёт второму ошибку `Conflict: terminated by other getUpdates request`, ответы будут теряться. Перед локальным запуском остановите сервис на Railway, а перед деплоем — локального бота. Защита через `.bot.lock` работает только в пределах одного компьютера.

## Структура проекта

```
pet-water-bot/
├── bot.py            # основной код бота и миграция JSON → SQLite
├── requirements.txt  # зависимости
├── Procfile          # команда запуска для Railway (worker)
├── .env.example      # пример переменных окружения
├── .env              # ваш токен (не публикуйте этот файл)
└── bot.db            # база SQLite (создаётся ботом; путь меняется через DB_PATH)
```

## Как получить токен

1. Откройте Telegram и найдите [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` и следуйте инструкциям.
3. Скопируйте выданный токен в файл `.env`.
